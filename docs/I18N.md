# i18n status: applies narrowly; English-only operator surface

mrf-honest now has a local operator CLI. Its human-readable progress, error, and inspection output
is English-only; the documentation is also English-only. This is an explicit current limitation,
not an assertion that internationalization is irrelevant.

The machine-readable CLI output is canonical JSON with stable English field names. Finding codes
are stable identifiers and finding definitions are source-cited, but their descriptions are not
localized. CMS schema keys, US institutional identifiers, and USD amounts remain unchanged because
they are properties of the source data rather than presentation choices.

**Scope note:** the source data is US price-transparency filings; amounts are USD and field
names are fixed by CMS schemas. That is a property of the data, not a localization decision.

**Revisit before:** phase 5 ships a public static site or API, or the CLI is presented to people
other than technical operators. A public price-comparison site is a civic-adjacent surface; its
language, currency, number, and date presentation must be decided before implementation rather
than inherited silently from this CLI.
